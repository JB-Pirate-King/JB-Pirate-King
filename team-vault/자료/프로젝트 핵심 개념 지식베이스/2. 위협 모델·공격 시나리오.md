# 2. 위협 모델·공격 시나리오

## 핵심 전제: 왜 AIS/NMEA 공격이 가능한가
모든 시나리오의 뾌리는 **NMEA 프로토콜의 구조적 보안 부재**다. 출처(NMEA 동적 플러딩 논문/포스터)는 이를 반복적으로 명시한다.
- **인증(authentication)·암호화(encryption)·무결성 검증(integrity check) 부재.** NMEA는 차량용 CAN/J1939를 기반으로 단순성·상호운용성에 초점을 두고 설계되어, 보안 기능이 처음부터 빠져 있다.
- 그 결과 **누구나 위조 메시지를 주입(injection)할 수 있고, 수신측은 진위를 검증하지 못한다.** OpenCPN 같은 항해 SW는 형식만 맞으면 그대로 신뢰·표시한다.
- IMO 권고로 일부 선박이 IP 기반 필터링/IDS를 쓰지만, **IP 필터링은 스푸핑·주소 변조에 취약하고 플러딩 같은 저수준 트래픽 공격을 막지 못한다.** 또 제조사별 독자(Proprietary) 명령어 체계 탓에 보안 정책 일반화·자동화가 어렵다.
- 연구 격차: 차량용 J1939 보안 논문이 수십만 편인 데 비해 "NMEA security"는 약 1천여 편, 대부분 개념·단순 구현 수준에 머물러.
→ **우리 프로젝트에서의 의미:** 프로토콜 자체를 고칠 수 없으므로(레거시·표준), 방어선은 "수신된 AIS/NMEA 데이터의 행동 패턴이 이상한지"를 ML로 판밄하는 **이상 탐지(anomaly detection) 계층**이 된다. 출처들이 일관되게 권하는 대응 3종(화이트리스트, 시각 필터링, **이상 탐지**) 중 마지막이 우리 DCdetect IDS의 존재 이유다.

## 1. NMEA 동적 플러딩 공격 (Dynamic Flooding / Ghost Ship Swarm)
WISA 2025 포스터·논문("NMEA Under Siege")의 핵심 시나리오.

### 정의
정적·구조적 취약점 지적에 그쳤던 기존 연구와 달리, **항해 조건에 연계해 위조 NMEA 메시지를 동적으로(좌표를 계산해 가며) 대량 반복 송출**하는 공격. 대표형이 **유령 선박 대군(Ghost Ship Swarm)** 이다.

### 작동 메커니즘
1. **메시지 타입:** AIS Type 1(위치 보고) AIVDM 메시지 사용. MMSI·위경도·속도(SOG)·침로(COG) 등을 담는다.
1. **페이로드 조작:**
  - **MMSI:** 실제 미사용 임의 번호를 `MMSI_START`부터 순차 증가시켜 각 유령 선박을 식별.
  - **위도/경도:** 핵심 조작부. `letter_map`/`get_ship_positions` 함수로 **특정 문자열 형태를 이루는 수천 개 좌표를 동적 생성** (BASE_LAT/BASE_LON 기준 + DOT/CHAR/PIXEL 파라미터).
  - **기타 필드:** 속도·침로 등은 임의의 유효 값으로 채워 메시지 유효성을 유지.
1. **플러딩 전송:** `make_aivdm_sentence`로 만든 NMEA 문장을 가상 시리얼 포트로 고빈도(`time.sleep(0.01)`, 포스터 기준 **약 100Hz**) 연속 송출.

### 실험 환경 · 결과 (재현 사실)
- **환경:** Windows PC + OpenCPN + `com0com`(가상 시리얼 포트 드라이버) + Python 3.x + PySerial. 예: COM8(스크립트 출력) ↔ COM9(OpenCPN 입력) 가상 연결.
- **결과:** 기준 좌표를 중심으로 **"WHS3" 형상의 약 10,000척 유령 선박**이 전자해도에 실시간 표출. 육지·해상을 가리지 않고 표시됨. 정상 AIS 데이터가 유령 선박에 가려 **유효 선박 식별 불가** 상태 발생.

### 공격 목표 · 영향
- **ECDIS/레이더 화면 교란:** 허위 아이콘이 상황 인지를 방해, 충돌 위험 오판 유도.
- **정보 과부하·중요 알림 은닉:** 정상 메시지 처리 지연, 핵심 항해 정보 수신/반영 지연.
- 본질: 단순 데이터 변조를 넘어 **운항자의 상황 인식(situational awareness) 자체를 저하**시키는 인지 공격.
→ **우리 프로젝트에서의 의미:** 동적 플러딩은 "물리적으로 불가능한 이동", "동일 MMSI 단시간 다중 메시지", "비정상 밀도/출현 위치" 같은 시그니처를 남긴다. 출처가 제안한 방어 3종(화이트리스트 MMSI, 저신뢰 타깃 시각 필터링, **메시지 빈도·선박 밀도 기반 이상 탐지**)은 우리 IDS의 피처/시나리오 설계와 직결된다.

## 2. 합성 AIS 신호(ghost ship) 생성 — 공격 도구의 내부 구조
`ghost ship gen.md`는 위 플러딩을 실제로 만들어내는 **AIS 신호 합성기 PoC**다. 우리 IDS의 평가 시나리오·공격 데이터 생성 관점에서 중요.

### 합성 메커니즘 (NMEA 비트 인코딩)
- **전송:** 본문 기준 `localhost:1111` **UDP**로 NMEA 0183 송신 (포스터의 시리얼 변형과 별개 채널).
- **AIVDM 비트 스트림 직접 구성:** `build_vdm`이 AIS **Type 1(168비트)** 페이로드를 비트 단위로 push. 필드 폭이 표준 그대로다:
  - Message type(6), Repeat(2), **MMSI(30)**, Nav status(4), ROT(8), **SOG(10, 1/10노트)**, Position accuracy(1), **Longitude(28, 1/10000분)**, **Latitude(27)**, **COG(12, 1/10도)**, True heading(9), Timestamp(6) 등.
  - 6비트 → ASCII 인코딩(payload armoring), `nmea_checksum`으로 `$~*` 사이 XOR 체크섬 부여.
- **선박 이름 표시:** `build_vsd`가 AIS **Type 24 Part A**(선박명, 최대 20자)를 별도 송출해 OpenCPN에 이름 노출.

### 공격 패턴(선단 형태) — GUI 커스터마이저
실제 GUI 도구는 5가지 떼 형태를 파라미터로 제공한다:
| 패턴 | 특징 |
| 원형 선단 | 중심 좌표 주변 원형 항행(예 15척). 접선 방향 COG, 속도 변동 |
| 격자 선단 | rows×cols 격자 배치 + 미세 드리프트 |
| 나선형 | 회전수·최대반경 기반 스파이럴 |
| 랜덤 확산 | spread 반경 내 무작위 위치/침로 |
| JBU 글자 | J·B·U 알파벳 형상 waypoint를 따라 이동(문자 시각화) |
- 부산 앞바다(예: `CENTER_LAT 35.05, CENTER_LON 129.15`) 기준, `nav_status` 0/1/5(항행/닿내림/계류)도 설정. 중앙에 **정상 정박 선박 1척(MMSI 440123456)** 을 섞어 정상/이상 혼재를 모사.
- 위치 갱신은 SOG(노트)를 도/초로 환산해 이동시키므로 **거리·속도가 물리적으로 정합**하게 움직인다(단순 점멸이 아님).
→ **우리 프로젝트에서의 의미:** 이 합성기는 IDS 학습/평가용 **공격 샘플 생성기**로 직결된다. 베이스 피처(sog, cog, heading, status, dist_km 등)와 파생 피처(dist_speed_err, anchor_suspicion 등)는 정확히 이런 합성 선박의 **물리 정합성/비정합성**을 잡아내도록 설계돼 있다.

## 3. S-100 GPS 신호 조작 — STRIDE 위협 모델
"S-100 표준 적용에 따른 ECDIS GPS 신호 조작 위협 시나리오 분석" 포스터(Team SeaBugs).

### 배경
- **S-100**은 AIS·GPS·수로 서버·기상 데이터 등과 **RESTful API로 실시간 통신**하는 개방형 구조. 상호운용성·실시간성이 강화된 대신 **외부 사이버 공격 벡터가 급증**하고, S-57보다 정교한 보안 분석이 필요하다.

### STRIDE 분류 (ECDIS 적용)
| 요소 | ECDIS에서의 위협 |
| **S**poofing | GPS·AIS 신호 위조로 잘못된 위치 정보 전달 |
| **T**ampering | 해도 데이터(.000 파일 등) 변조·조작 |
| **R**epudiation | 로그 미기록 → 공격 행위 부인 가능 |
| **I**nfo Disclosure | 외부 연동 과정의 해양 작전 정보 유출 |
| **D**enial of Service | 해도 파일 크기 조작·반복 요청으로 ECDIS 다운 |
| **E**levation of Privilege | 미검증 API 호출로 관리자 권한 상승 |

### 최고 위험 시나리오 2종 (STRIDE 평가 결과)
1. **변조 ENC(.000) 주입:** 해도 서버–단말 간 **TLS 미적용 + ENC 무결성 검증 부재** 상황에서 **중간자 공격(MITM)**으로 변조된 ENC 파일을 주입 → 잘못된 항로 표시 → **좌초·충돌 유도**.
1. **NMEA 가로채기·조작:** AIS/GPS 신호 위조 환경에서 NMEA 메시지를 가로채 조작 → 자율 운항 시스템 등과 연동 시 **잘못된 위치 표시 → 충돌 위험 증가**.

### 전파성
공격 트리 분석상, 이 위협은 단일 선박에 그치지 않고 **항로 혼잡·교차 구역에서 다수 선박의 연쇄 사고**로 확산될 수 있고, 변조 정보가 관제센터/인근 선박으로 전파되어 **해상 교통 시스템 전체 신뢰성 저하**로 이어질 수 있다. 권고 대응: 데이터 무결성 검증, 디지털 서명, 보안 채널, 표준화된 해양 사이버보안 프레임워크.
→ **우리 프로젝트에서의 의미:** STRIDE의 Spoofing/Tampering이 곧 우리가 탐지하는 "위치·항로 거짓말". GPS/AIS 스푸핑은 **선위가 물리적으로 모순**되는 흔적을 남기므로(점프, 거리-속도 불일치), 우리 IDS의 핵심 탐지 대상과 정확히 겹친다.

## 4. S-52 시각정보 변조 — 표시 계층 공격
"A Study on the Risks of Visual Information Alteration Using the S-52 Presentation Library" 논문.

### 새로운 위협 벡터: '데이터'가 아니라 '표시(Presentation)'
- ECDIS는 ENC 객체/속성을 **IHO S-52 표준의 표시 라이브러리(Presentation Library)** 로 심볼·색상화한다. S-52는 **데이터와 항해사 사이의 최종 인터페이스(최후의 보루)**.
- 기존 보안 연구는 **입력 데이터 무결성**(GPS 스푸핑, AIS 변조, S-63 암호화)에 집중. 그러나 **입력이 정상이어도 표시 라이브러리가 변조되면** 항해사는 왜곡된 화면을 보게 된다. 이 표시 계층 보안은 선행 연구가 **전무**했다.

### 공격 메커니즘 (실증)
- 대상 파일: `s57data/chartsymbols.xml` 의 **Lookup Table**(심볼 조회 테이블). 시각 정보 생성의 핵심.
- **파일 교체(File-Swap) 공격:** 원본 백업 → "OBSTRN"(수중 장애물) 키워드 lookup 블록 전부 **주석 처리** → 원본 삭제 후 사본을 원래 파일명으로 교체.
- 결과: OpenCPN(검증 버전 5.10.2-0 / 본문 일부 v5.8.0 언급) 재시작 시 **OBSTRN 심볼이 전부 사라짐.** 수정 안 한 난파선(WRECKS)은 정상 표시 → **선별적·은밀한 공격** 입증. 경고 없이 "거짓으로 안전해 보이는" 해도가 표시됨.

### 근본 원인
OpenCPN이 **표시 라이브러리 파일의 해시/서명을 검증하지 않고, 파일이 없어도 실행되며, 파일명만 일치하면 내용을 신뢰**하는 총체적 무결성 검증 부재.

### 제안 방어
- 기술: `chartsymbols.xml` 등에 **암호학적 해시(SHA-256)/디지털 서명 검증** 도입, 불일치 시 로드 거부·안전모드; **필수 파일 존재 검사**.
- 절차: 보안 채널 기반 **소프트웨어 공급망(Supply Chain) 관리**, 항해사 교차검증(RADAR·예비 ECDIS) 교육.
→ **우리 프로젝트에서의 의미:** 이 공격은 **AIS 데이터 흐름 바깥(파일 시스템·HMI)** 에서 일어나므로 AIS 이상탐지 ML만으로는 못 잡는다. 우리 IDS의 사각지대를 규정하는 사례 — 데이터 행동 탐지(ML) + 파일 무결성 검증(별도 계층)이 함께 필요함을 보여준다.

## 5. ECDIS "Edition 0" 차트 삭제 오용 — 절차적 위협
"ECDIS 차트 삭제 업데이트의 오용 가능성과 절차적 대응 방안 연구". (포커스 영역에 명시되어 함께 정리)

### 메커니즘
- **삭제형 업데이트(Edition 0):** Transas Navi-Sailor 3000 ECDIS의 실제 기능. 차트를 구버전으로 간주할 때 Edition 번호를 '0'으로 설정한 갱신 파일로 해당 차트를 해도 목록에서 제거.
- 문제: **사용자의 단순 확인(Yes 클릭)만으로 삭제 완료.** 별도 검증 없음 → 실수·악의 모두에 취약.
- S-63은 Blowfish 암호화·디지털 서명·해시 검증으로 데이터를 보호하지만, **삭제 절차 같은 운용 측면**은 다루지 않는다. Edition 0 삭제는 "허용된 정상 동작"이라 별도 방지 수단이 없다.

### 오남용 시나리오 3종
1. **실수 클릭:** 항해 중 팝업 경고 미인지 → 현재 항로 차트 실시간 삭제 → 해역 정보 공백.
1. **악성 패키지 삽입(Chart DoS):** 검증 안 된 USB/네트워크로 위조 Edition 0 주입 → Chart Manager가 정식 업데이트로 인식해 삭제 → **의도적 정보 비활성화 공격**.
1. **자동 스케줄러 충돌:** 자동 업데이트 모드에서 Edition 0이 사용자 확인 없이 적용되어 자동 삭제.

### 대응: 경량 Safe-Delete SOP (5단계)
대상 목록 확인 → 항로 공백 검토 → **관리자 이중 승인(선장)** → 백업 확인 → 삭제 후 로그/보고. 하드웨어 변경 없이 매뉴얼·교육만으로 도입 가능. (참고 사례: MAIB Kaami 좌초 사고 — ENC 셀 미적재·안전설정 오류.)
→ **우리 프로젝트에서의 의미:** 데이터/표시가 아니라 **운용 절차**가 공격면인 사례. AIS IDS와 직접 연결되진 않지만, "위협 모델"의 폭(데이터·표시·절차)을 정의하는 데 필요하며, Chart DoS 역시 무결성 검증·로그(Repudiation 방지) 부재라는 공통 뾌리를 공유한다.

## 종합: 공격면 계층화와 우리 IDS의 위치
| 공격 계층 | 대표 위협(출처) | 가능 원인 | 우리 IDS 탐지 가능성 |
| 데이터 입력(주입) | NMEA 동적 플러딩·ghost ship, GPS/AIS 스푸핑 | 인증·암호화·무결성 부재 | ✅ 핵심 대상 (행동/물리정합 이상) |
| 데이터 전송 | 변조 ENC MITM 주입(S-100) | TLS·ENC 무결성 검증 부재 | △ 위치모순으로 일부 간접 탐지 |
| 표시(Presentation) | S-52 chartsymbols.xml 변조 | 파일 해시/서명 미검증 | ✕ (별도 무결성 검증 필요) |
| 운용 절차 | Edition 0 차트 삭제 오용 | 승인·로그 절차 부재 | ✕ (SOP/절차로 대응) |
**일관된 결론:** 다섯 출처 모두 결국 **무결성·인증·검증의 부재**라는 같은 뾌리를 가리키며, 공통 대응으로 **이상 탐지(anomaly detection)** 를 든다. 우리 DCdetect 기반 AIS IDS는 이 중 **데이터 입력 계층의 행동 이상**을 ML로 탐지하는 방어선이고, 표시/절차 계층은 무결성 검증·SOP 등 보완 통제가 필요하다는 점이 위협 모델 전체에서 드러난다.
