# 3. OpenCPN 호스트 보안 — 취약점 클래스

> ⚠️ 이 페이지는 팀이 책임있게 조사·문서화한 OpenCPN 보안 연구(ZDI 리포트)를 **개념·근본원인·방어적 의미 중심**으로 요약한 것입니다. 단계별 PoC 익스플로잇 절차·페이로드는 의도적으로 제외했으며, 원본 리포트는 team-vault `CCIT/취약점 리포트/`에 보존됩니다.

## 개요: 무엇을, 왜 모았나
우리 팀(CCIT)은 항해 소프트웨어 **OpenCPN**(오픈소스 ECS/ECDIS)과 그 **플러그인** 생태계를 분석해 **6종의 실증 취약점**을 정리했다. 대부분 ZDI(Zero Day Initiative) 리포트로 정리된 책임있는 취약점 공개 사례다.
이 분석의 핵심 관점: OpenCPN은 **플러그인을 신뢰**하고, **외부 리소스(차트 XML/ZIP, 심볼 정의 파일, 모델 .cof)를 검증 없이 로드**한다. 이 "신뢰 경계의 부재"가 모든 취약점의 공통 뾌리다.
> → 우리 프로젝트에서의 의미: 우리 AIS 이상탐지(IDS)는 바로 이 OpenCPN 위에 C++ 플러그인으로 얇힌다. 호스트 플랫폼의 신뢰 경계가 못 잡으면 우리 모델·임계값 파일(`model.onnx`/`scaler.json`/`threshold.txt`)도 같은 신뢰 경계 안에서 위협받을 수 있다. 즉 "호스트 보안"은 우리 탐지 시스템의 가용성·무결성 전제 조건이다.

## 공통 메커니즘 — 신뢰 경계 부재 (Missing Trust Boundary)
| 개념 | 설명 |
| **블랙리스트 only 검증** | 플러그인 로드 시 화이트리스트/서명/경로 검증 없이 "차단 목록에 없으면 통과" 방식만 사용 → 임의 라이브러리 로드 허용 |
| **리소스 파일 무검증** | 차트 XML·ZIP, 심볼 정의 XML, WMM `.cof` 등 외부 파일을 해시/서명/길이/경로 검증 없이 그대로 읽음 |
| **셰 직접 전달** | 사용자/설정 파일의 문자열을 이스케이프 없이 OS 셰에 전달 |
→ 우리 프로젝트에서의 의미: 모델 산출물도 "파일명만 맞으면 로드"되는 동일 패턴 위에 놓인다. 호스트에 무결성 검증(해시/서명)이 없다는 점을 인지하고 배포 파이프라인을 설계해야 한다.

## 취약점 요약 (6종)
각 항목은 **유형·대상 버전·취약 위치·근본 원인·영향·수정 방향**만 기록한다(익스플로잇 절차 제외).

### 1) Code Injection → RCE (플러그인 로더)
- **대상**: OpenCPN 5.11.3 / `plugin_loader.cpp` → `PluginLoader::LoadPlugIn()` (Ubuntu 24.04)
- **근본 원인**: 라이브러리 로드 시 **블랙리스트 검증만** 존재하고 서명·경로·화이트리스트 검증이 없음. 차단 목록만 통과하면 임의 동적 라이브러리의 초기화 코드가 프로세스 권한으로 실행됨.
- **영향**: 프로세스 권한 원격 코드 실행(RCE).
- → 의미: **우리 IDS 플러그인 자체가 이 로더로 적재**된다. 정상 플러그인을 가장한 악성 모듈이 탐지 로직을 우회/무력화하거나, 배포 채널이 신뢰 사슬의 약한 고리가 될 수 있다.

### 2) Command Injection (Launcher 플러그인)
- **대상**: OpenCPN 5.12.0, Launcher Plugin v1.3.5 / `launcher_pi.cpp` → `OnBtnClick` → `wxExecute` (Windows 등)
- **근본 원인**: 설정 파일의 명령 문자열을 **필터링·이스케이프 없이** OS 셰에 그대로 전달. 셰 메타문자로 명령 연쇄 가능.
- **영향**: 임의 명령 실행. (제안 수정: 화이트리스트 인자 필터링, 메타문자 이스케이프, 셰 우회 실행 API 사용)
- → 의미: **설정 파일(.ini)이 공 코드 실행 경로가 되는** 사례. 우리도 설정/경로 입력을 받는 지점이 있다면 "데이터가 명령이 되는" 패턴을 경계해야 한다.

### 3) Path Traversal / File Overwrite (CLI 플러그인 임포트)
- **대상**: OpenCPN 5.11.3 / `Console.cpp` → `import_plugin()` (`ImportedMetadataPath(metadata.name)`) (Ubuntu 24.04)
- **근본 원인**: 메타데이터의 **이름 필드에 대한 경로 검증이 없음** → 이름이 그대로 파일 경로가 되어 상위 디렉터리로 탈출 가능.
- **영향**: 임의 경로에 파일 생성/덮어쓰기.
- → 의미: "이름 필드"가 파일시스템 경로로 직결되는 패턴. 우리 모델/스케일러 파일이 임의 경로에 덮어쓰일 가능성과 직결.

### 4) Chart Downloader — Zip Slip (Path Traversal → RCE)
- **대상**: Chart Downloader Plugin 5.12.0-0 / `chartdldr_pi.cpp` → `ExtractZipFiles()` (Windows·Linux 동일)
- **근본 원인**: 외부 카탈로그에서 받은 ZIP을 풀 때 **엔트리 이름의 상위경로 시퀀스를 제거하지 않음**(전형적 Zip Slip). 경로 정규화·포함여부 검사 부재.
- **영향**: 압축 해제 시 대상 디렉터리 밖으로 파일 쓰기 → 원격 코드 실행/시스템 파일 변조 가능. **물리 접근 없이 원격**에서 성립 가능해 위험도가 가장 높음. (제안 수정: 정규화 후 대상 디렉터리 하위 검사, `..` 포함 엔트리 거부, 확장자 화이트리스트)
- → 의미: "정상 업데이트로 위장한 악성 차트"는 우리 탐지 모델 밖의 **공급망 위협**. 우리 IDS가 도는 호스트 전체가 위협받는다.

### 5) chartsymbols.xml 심볼 변조 (OBSTRN 은닉)
- **대상**: OpenCPN 5.8.0 / `s57data/chartsymbols.xml` (해시/서명 미검증)
- **근본 원인**: 심볼 정의 파일을 무결성 검증 없이 로드. 파일이 없어도 실행되고 이름만 같으면 내용을 신뢰. 공격자가 수중 장애물(OBSTRN) 심볼 조회 블록만 선별 대체 → 화면에서 은닉.
- **영향**: 항해자가 수중 암초/장애물을 인지 못한 채 항해 → 충돌/침몰 위험(동일 계열 WRECKS는 영향 없어 선밄성 입증).
- → 의미: AIS 신호 조작이 아닌 **"렌더링/표시 계층을 속이는"** 공격. 우리 IDS의 탐지 범위 밖 — 화면 표시 무결성도 보완 위협임을 규정.

### 6) WMM 플러그인 힙 버퍼 오버플로 (.cof 파싱)
- **대상**: OpenCPN 5.12.0 (Win 32bit) / `WMM_pi.dll` — `.cof` 헤더 파싱 (`sscanf`)
- **근본 원인**: `.cof`의 `edit_date` 등 필드 **길이를 검증하지 않고** 복사 → 힙 영역 초과. 해제(free) 경로에서 비정상 블록 감지로 크래시, 임의 코드 실행 가능성.
- **영향**: 크래시/임의 코드 실행 가능성. (제안 수정: 길이 제한 파싱, 버퍼 초과 시 중단, ASAN/Heap guard 빌드)
- → 의미: 외부 모델/데이터 파일 파싱 시 **길이 검증 누락이 메모리 손상으로 직결**. 우리도 ONNX/스케일러/임계값 등 외부 파일을 읽을 때 동일한 입력 검증 원칙을 적용해야 한다.

## 종합 시사점
- **공통 약점**: 플러그인·외부 리소스에 대한 **무결성/입력 검증 부재**(블랙리스트만, 길이/경로/서명 미검증, 셰 직접 전달).
- **공격 표면 분류**: ① 코드 실행(1·2·4·6) ② 파일시스템 무결성(3·4) ③ 표시 무결성(5).
- **우리 IDS는 이 호스트(OpenCPN) 위에서 동작**하므로, 호스트 신뢰 경계의 취약성은 곧 우리 탐지 시스템의 가용성·무결성 전제 조건이다. 배포 모델 파일의 해시 검증 등 보완 통제를 고려할 근거가 된다.
