# ECDIS 차트 삭제 업데이트의 오용 가능성과 절차적 대응 방안 연구 

## 1. 서론
전자해도(ENC, Electronic Navigational Chart)는 선박의 항해 안전을 위한 필수 요소이며, 이를 갱신하고 관리하는 시스템인 ECDIS(Electronic Chart Display and Information System)는 지속적인 업데이트를 통해 최신 항해 정보를 유지한다. 본 연구에서 다루는 삭제형 업데이트(Edition 0)는 Transas 사의 Navi-Sailor 3000 ECDIS 시스템에서 실제로 사용되는 기능이다. 이 시스템에서는 차트가 구버전으로 간주될 경우, Edition 번호를 '0'으로 설정한 삭제형 갱신 파일을 통해 해당 차트를 선박 해도 목록에서 제거한다. 이러한 구현 방식은 사용자의 단순 확인만으로 삭제가 완료된다는 구조적 특징을 가지며, 사용자 실수나 절차적 오류에 매우 취약하다.
실제로 MAIB(영국 해양사고조사국)의 Kaami 사고 보고서에 따르면, 항해 중 ENC 셀의 미적재와 ECDIS 안전 설정 오류로 인해 좌초 사고가 발생한 바 있다[1]. 이는 단순한 기술 문제가 아니라 절차적 결함이 중대한 항해 사고로 이어질 수 있음을 보여주는 대표 사례다. 본 연구는 이러한 "Edition 0" 삭제형 업데이트의 오남용 가능성을 중심으로 위험 시나리오를 분석하고, 이를 방지하기 위한 경량 Safe-Delete SOP(Standard Operating Procedure)를 제안하고자 한다. 기존의 보안 연구들이 S-63 데이터 보호 구조나 ENC 암호화 메커니즘에 집중되어 있는 반면, 삭제형 업데이트와 같은 운용 절차의 안전성 문제는 상대적으로 주목받지 못했다. 따라서 본 논문은 ECDIS 운영 절차의 사각지대를 조명하며, 실무 적용 가능한 경량 절차의 필요성과 구조를 제시한다. 


## 2. 삭제형 업데이트 기능과 보안 한계
전자해도 시스템은 국제수로기구(IHO)가 정한 S-57 형식의 ENC 데이터를 기반으로 하며, 이를 보호하기 위해 IHO는 S-63 표준을 제정하였다. 이 표준은 ENC 파일에 대한 Blowfish 기반 암호화, 디지털 서명, 해시값 검증을 포함한 무결성 보호 체계를 통해 데이터 위조 및 변조를 방지하는 데 목적이 있다[4]. 하지만 이 표준은 데이터 자체의 보호에 초점이 맞춰져 있으며, 차트 삭제 절차와 같은 운용 측면의 절차적 보안 문제는 다루고 있지 않다. 실제로 ENC 업데이트는 대부분 이동식 미디어(예: USB)를 통해 수행되며, 이 과정에서 악성 Edition 0 파일이 삽입될 수 있다. IHO의 보안 지침은 무결성 확인과 인증 절차를 강조하지만, Edition 0 파일을 통한 차트 삭제 자체는 허용된 정상 동작으로 간주되기 때문에, 의도치 않은 삭제나 악성 활용에 대한 별도의 방지 수단은 마련되어 있지 않다[2].
IMO(International Maritime Organization)는 ECDIS의 성능 기준과 운용 지침을 통해 정기적 차트 업데이트의 중요성을 강조하고 있으며, 시스템 간 상호운용성과 최신성 유지 등을 주요 항목으로 포함하고 있다. 그러나, ECDIS가 Edition 0 삭제 기능을 어떻게 구현하고 있는지에 대한 언급은 없으며, 삭제형 업데이트의 취급 기준이나 승인 절차에 대한 세부 규정도 제시하고 있지 않다. Park et al.[3]의 연구에서는 ECDIS에 대한 STRIDE 기반 위협 모델링을 수행하고, 사이버 보안 관점에서 외부 장치 접근 제한 및 망 분리(Network Segregation)를 주요 대응 방안으로 제시하였다. 그러나 이 역시 소프트웨어 또는 시스템 네트워크 차원의 방어를 중심으로 하고 있어, 운영자 실수나 절차적 문제로 인한 정보 삭제와 같은 위협에는 취약할 수 있다. 따라서 본 연구에서는 기존 기술적 보호 체계와 별도로, 차트 삭제라는 특수한 행위에 대해 운용 절차(SOP)를 중심으로 한 예방적 대응 프레임워크의 필요성을 제기한다.



## 3. 오남용 시나리오 및 Safe-Delete SOP

### **3.1 Edition 0 오남용 시나리오**
**시나리오 1: 항해 중 실수 클릭으로 인한 차트 삭제**
항해사가 갱신 작업 중 Chart Manager의 Edition 0 삭제 팝업에 대해 경고를 인지하지 못하고 Yes를 클릭한 경우, 현재 항로 상에 필요한 차트가 실시간으로 삭제될 수 있다. 이는 안전 항해를 위한 해역 정보 공백을 초래하며, 즉각적인 복구가 어렵다.
**시나리오 2: 악의적인 업데이트 패키지 삽입**
공급 경로가 검증되지 않은 USB 또는 네트워크를 통해 위조된 Edition 0 업데이트 파일이 삽입되면, 선박 내부 Chart Manager는 이를 정식 업데이트로 인식하고 차트를 삭제할 수 있다. 이는 의도적 정보 비활성화(Chart DoS) 공격으로 간주될 수 있다[2].
**시나리오 3: 자동 스케줄러와 Edition 0의 충돌**
일부 ECDIS는 자동 업데이트 모드를 지원하는데, 이 경우 Edition 0이 포함된 업데이트가 사용자의 직접 확인 없이 적용되어 차트가 자동 삭제되는 상황이 발생할 수 있다. 실제로 Transas Navi-Sailor 3000 ECDIS에서는 Edition 0 업데이트가 삽입되었을 때, Chart Manager는 이를 정상 업데이트로 인식하고 사용자에게 삭제 여부를 묻는 단순 팝업만 제공한다. 사용자가 'Yes'를 선택하면 별도의 검증 절차 없이 해당 차트가 즉시 삭제되며, 이는 악의적인 삭제형 갱신 파일을 통한 DoS 공격 시나리오를 현실화할 수 있게 만든다.

📌 **[그림 1] Edition 0 오남용 시나리오 데이터 흐름도 (DFD)**
> 사용자 입력 → Chart Manager → Edition 0 적용 → 검증 절차 없음 → 차트 삭제
  악성 패키지 → Chart Manager → 무결성 확인 생략 → 삭제 수행

### 3.2 Safe-Delete SOP 설계안
Safe-Delete SOP는 ECDIS 시스템에 Edition 0 업데이트를 적용하기 전후의 절차를 표준화하여, 실수 및 악의적 행위로 인한 차트 삭제를 예방하는 경량 운용 프로세스다. 이 절차는 별도의 하드웨어 변경 없이, 운용 매뉴얼과 교육만으로도 도입 가능하며, 선박의 작업 흐름에 자연스럽게 통합될 수 있도록 설계되었다.
📌 **[표 1] Safe-Delete SOP 5단계 요약표**
| 단계 | 절차 내용 | 담당자 | 확인 방식 | 기록 여부 |
| 1단계 | Edition 0 적용 대상 차트 목록 확인 | 항해사 | 수동 점검 | O |
| 2단계 | 차트 삭제 시 항로 공백 여부 검토 | 항로 담당 | 항적 분석 도구 | O |
| 3단계 | 관리자 이중 승인 요청 | 항해장 및 선장 | 전자서명 또는 구두 승인 | O |
| 4단계 | 삭제 전 차트 백업 파일 존재 확인 | IT 책임자 | 파일 경로 점검 | △ |
| 5단계 | 삭제 수행 후 로그 기록 및 보고서 생성 | 항해사 | 시스템 로그 저장 및 수기 보고 | O |
※ “△”는 수작업 또는 전용 도구에 의한 확인 병행 가능 항목
향후에는 UI 상에 SOP 체크리스트를 자동 표시하거나, Edition 0 삭제 전 항적 시뮬레이션 기능을 연동하는 것도 가능하다.


## 4. 결론
본 연구는 ENC 시스템의 갱신 절차 중 하나인 "Edition 0" 삭제형 업데이트 기능의 위험성을 조명하고, 오남용 시나리오를 기반으로 실무 적용 가능한 Safe-Delete 절차를 제안하였다. 해도 삭제는 단순한 오류가 아닌 항해 안전을 위협할 수 있는 중대한 행위이므로, 경량 SOP 형태의 절차 기반 대응이 요구된다.
제안된 SOP는 별도의 시스템 변경 없이 현장 적용이 가능하며, 사용자 실수 및 악의적 행위 모두에 대해 최소 수준의 방어 체계를 제공할 수 있다. 특히 ECDIS의 복잡한 사이버 위협 요소 중, 비교적 간과되어 온 ‘절차적 실수’를 방지한다는 점에서 실무적 의의가 크다.
향후 연구에서는 다양한 ECDIS 제조사별 UI 차이 분석, 자동화된 SOP 알림 기능, Edition 0 파일의 디지털 서명 기반 무결성 검증, 로그 기반 위협 탐지 기능 연계 등을 통해 제안된 프레임워크의 현실적 완성도를 높일 수 있을 것이다.
