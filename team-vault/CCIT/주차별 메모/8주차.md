TranAD가 DCdetect의 약점(D4-Mimicry, COG/HDG 불일치)을 보완하면서도 DCdetect 강점(E5-Shadow, F1-FeatSmooth)은 유지됨.

---


### 앙상블 방식
**가중 평균 앙상블 (Weighted Average Ensemble)**
`score = 0.7 × MSE(DCdetect) + 0.3 × MSE(TranAD)`
OR 앙상블은 오탐율이 `1-(0.9)²≈19%`로 통제 불가.
가중 평균은 정상 데이터의 score 분포에서 목표 오탐율(5%)에 해당하는
임계값을 자동으로 설정할 수 있어 오탐율을 정밀하게 제어 가능.

---


### 모델 구조 
**DCdetect (KDD 2023)**
Channel-wise Attention(피처 간 관계) + Patch-wise Attention(시간 구간 패턴)의 이중 어텐션.
seq=10을 5개 패치(patch_size=2)로 분할해 처리.

**TranAD (VLDB 2022)**
두 Transformer Decoder(D1, D2)로 self-conditioning 학습.
학습 초반엔 재구성, 후반엔 adversarial 증폭으로 이상 시점 MSE를 벌림.
window=10 단기 시퀀스를 염두에 두고 설계된 모델.

# 스노트 ML
현재 공식 지원 모델에서는 http관련 ml만 지원
 `http_param_model`  (HTTP 파라미터 기반 SQL Injection, XSS 탐지)

---


AIS 피처를 HTTP URI 파라미터로 인코딩해서 Snort에 흘려보내면, snort_ml inspector가 그대로 받아서 하는 느낌

---

**의의**
- SnortML 소스 수정 없이 기존 파이프라인 재활용
- Snort 플러그인 개발 없이 구현 가능
- LibML/TFLite 포맷 호환으로 SnortML 생태계 활용

**한계**
- float 피처 → ASCII 문자열 → 바이트 변환 과정에서 정보 간접화
- 시퀀스 구조가 문자열로 평탄화되어 ONNX 기반 방식 대비 탐지 성능 저하 가능
- HTTP 파이프라인 의존으로 실제 네트워크 환경에서 오버헤드 발생
