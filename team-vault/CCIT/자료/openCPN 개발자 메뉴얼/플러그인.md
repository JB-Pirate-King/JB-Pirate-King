# 플러그인

## 1. 전제 조건 및 준비물
테스트를 위해서는 빌드가 완료된 다음 두 가지 파일이 필요합니다. (예시: `oesenc` 플러그인)
- **타르볼 파일:** `oesenc-pi-1.2.0-3-flatpak-18.08.tar.gz` (플러그인 본체)
- **메타데이터 파일:** `oesenc-plugin-flatpak-18.08.xml` (플러그인 정보)

## 2. 기본 검증 단계
- **타르볼 구조 확인:** 압축을 풀고 내부 디렉토리 구조가 OpenCPN 위키(Wiki)의 표준 레이아웃 사양을 따르는지 확인합니다.
- **로컬 설치 테스트:** OpenCPN의 플러그인 탭에서 **'플러그인 가져오기(Import Plugin)'** 버튼을 눌러 생성된 타르볼을 직접 설치해 봅니다. (가장 간단한 테스트 방법)
- **XML 구문 검사:** `xmllint` 도구를 사용하여 메타데이터 파일이 스키마(`ocpn-plugin.xsd`)에 맞는지 확인합니다.Bash
  `xmllint --schema ocpn-plugin.xsd path/to/plugin.xml`
- **URL 유효성 확인:** XML 파일 내에 기재된 타르볼 다운로드 링크가 올바른지 도구를 통해 확인합니다.Bash
  `python tools/check-metadata-urls path/to/plugin.xml`

## 3. 사용자 정의 카탈로그(`ocpn-plugins.xml`) 생성 및 테스트
여러 플러그인을 묶어서 관리하거나 공식 배포 전 전체 카탈로그를 테스트할 때 사용합니다.
1. **메타데이터 복사:** 로컬 설정 디렉토리(`~/.opencpn/plugins-metadata`)로 XML 소스들을 복사합니다.
1. **카탈로그 생성:** 제공된 파이썬 스크립트를 실행하여 통합 카탈로그 파일을 만듭니다.Bash
  `python ocpn-metadata generate`
1. **결과물 확인:** 생성된 `ocpn-plugins.xml` 파일을 OpenCPN 설정 경로에 두고 프로그램 실행 시 정상적으로 목록이 뜨는지 확인합니다.

## 4. 개인 카탈로그 게시 및 원격 테스트 (고급)
개발자가 자신의 GitHub 저장소를 활용해 사용자들에게 테스트용 카탈로그를 제공하는 방법입니다.
- **전문가 모드 활성화:** OpenCPN 설정 파일의 `[PlugIns]` 섹션에 `CatalogExpert=1`을 추가합니다.
- **GitHub 활용:**
  1. 자신의 GitHub 저장소에 수정된 메타데이터와 카탈로그를 푸시(Push)합니다.
  1. GitHub의 **'Raw'** 링크(예: `https://raw.githubusercontent.com/.../ocpn-plugins.xml`)를 복사합니다.
  1. OpenCPN의 [설정] -> [플러그인] -> [설정] 창에서 **'Custom URL'** 항목에 위 주소를 입력하여 목록을 불러옵니다.

## 요약
이 문서는 **"빌드된 파일이 표준에 맞는가?"**를 먼저 확인하고, **"로컬에서 직접 임포트"** 해본 뒤, 최종적으로 **"온라인 카탈로그 시스템(XML)"**을 통해 배포가 잘 되는지 검증하는 전체 워크플로우를 가이드하고 있습니다.
